# 🌐 Web App

Generate from BPMN models in the browser — no Gradle or Maven setup needed. The web app runs the same generator as the build plugins, so the output is identical. Three ways to use it:

1. **[Use the hosted version](#use-the-hosted-version)** — upload BPMN, download code
2. **[Self-host with Docker](#self-host-with-docker)** — run it on your own infrastructure
3. **[Call the REST API](#call-the-rest-api)** — from CI, scripts or any HTTP client

## Use the hosted version

Upload up to three BPMN files, pick the output language and engine, and download the generated Process API or the [JSON export](/surface/json). Nothing to install.

<a href="https://bpmn-to-code.miragon.io/static/index.html" target="_blank" class="web-app-button">
  Open Web App
</a>

Generated code uses the fixed package `com.example.process`; change it after downloading. Kotlin and Java output needs the `bpmn-to-code-runtime` dependency, which the app shows next to the result.

## Self-host with Docker

```bash
docker pull miragon/bpmn-to-code-web:latest
docker run -p 8080:8080 miragon/bpmn-to-code-web:latest
```

Then open `http://localhost:8080`. The image is on [Docker Hub](https://hub.docker.com/r/miragon/bpmn-to-code-web).

### Environment variables

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `8080` | Port the server listens on |
| `ALLOWED_CORS_ORIGINS` | all origins | Comma-separated list of allowed origins. Empty or `*` allows all |
| `IMPRINT_URL` | — | Shows an imprint link in the UI when set |
| `PRIVACY_URL` | — | Shows a privacy policy link in the UI when set |

### Endpoints

| Route | Purpose |
|-------|---------|
| `GET /` | Redirects to the UI at `/static/index.html` |
| `GET /health` | Health check, answers `{"status": "UP"}` |
| `GET /api/config` | Legal links and version the UI displays |
| `POST /api/generate` | Generates the Process API |
| `POST /api/generate-json` | Generates the [JSON export](/surface/json) |
| `GET /swagger` | Swagger UI for the routes above |

## Call the REST API

Both generation endpoints take one to three BPMN files, each Base64-encoded.

```bash
curl -X POST https://bpmn-to-code.miragon.io/api/generate \
  -H "Content-Type: application/json" \
  -d '{
    "files": [{
      "fileName": "bike-leasing.bpmn",
      "content": "'$(base64 < bike-leasing.bpmn | tr -d '\n')'"
    }],
    "config": {
      "outputLanguage": "KOTLIN",
      "processEngine": "ZEEBE"
    }
  }'
```

`outputLanguage` is `KOTLIN`, `JAVA` or `CSHARP`; `processEngine` is `ZEEBE`, `CAMUNDA_7` or `OPERATON`. `POST /api/generate-json` takes the same body with only `processEngine` in `config`.

### Response of `/api/generate`

```json
{
  "success": true,
  "files": [
    { "fileName": "BikeLeasingProcessApi.kt", "content": "// Generated by bpmn-to-code ...", "processId": "bikeLeasing" },
    { "fileName": "ServiceTasks.kt", "content": "// Generated by bpmn-to-code ...", "processId": null }
  ],
  "libraryFiles": [],
  "runtimeDependency": {
    "group": "io.miragon",
    "artifact": "bpmn-to-code-runtime",
    "version": "<version>",
    "gradleSnippet": "implementation(\"io.miragon:bpmn-to-code-runtime:<version>\")",
    "mavenSnippet": "<dependency>...</dependency>"
  }
}
```

- `files` holds one Process API per BPMN file plus the [shared definition files](/guide/generated-api#shared-definitions), which have `processId: null`.
- `libraryFiles` holds the sources of `bpmn-to-code-runtime` and `runtimeDependency` its coordinates. Both are left out for C#, which needs no runtime.
- `/api/generate-json` answers with `success` and `files` only, one `<processId>.json` per BPMN file.

### Errors

A failed request answers with `"success": false` and the reason in `error`.

| Status | When |
|--------|------|
| `400` | No files, more than three files, a model that fails [validation](/validate/), or two files that would be generated under one name |
| `500` | Any other failure |
