# v7 Migration Guide

## Am I affected?

| Surface | Affected |
|---------|----------|
| Maven goals | **yes if you rely on a default or on a relative path**: see [Maven parameters](#maven-parameters) |
| Generated C# (experimental) | **yes if a name used to get a trailing underscore**: see [C# names](#csharp-names) |

## Maven parameters

Every parameter of the Maven goals is required, as in Gradle and the command-line tool. The goals no longer default `baseDir` to `.`, `filePattern` to `src/main/resources/*.bpmn`, `outputFolderPath` to `src/main/kotlin` or `src/main/resources/bpmn-json`, `packagePath` to `de.emaarco.generated` or `outputLanguage` to `KOTLIN`. A missing parameter fails the build naming it.

A relative `baseDir` or `outputFolderPath` resolves against the module's directory, as in Gradle, and no longer against the directory Maven is started in. Configurations that prefix both with `${project.basedir}` keep working unchanged.

## C# names {#csharp-names}

C# no longer renames a name that clashes with a member it declares itself, as no other language does ([ADR 006](/contributing/adr/006-generated-api-shape)). Where 6.x appended `_`, generation now fails and names what to rename:

- an element whose type would be named like another element, as for `task` and `taskNode`,
- a variable named `all`, `inputs`, `outputs`, `processVariables` or `nodeVariables`,
- a call-activity mapping into `inputMappings` or `outputMappings`,
- a shared definition named like its class, such as a message `Messages`.
