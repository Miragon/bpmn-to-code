# v7 Migration Guide

## Am I affected?

| Surface | Affected |
|---------|----------|
| Maven goals | **yes if you rely on a default or on a relative path**: see [Maven parameters](#maven-parameters) |
| Validate task (experimental) | **yes**: it checks what the generation checks, see [Validation](#validation) |
| Testing library, custom rules | **yes**: mandatory rules always run, `BpmnValidationService` changed, see [Validation](#validation) |
| Code that catches core's exceptions | **yes**: see [Rejected models](#rejected-models) |
| Generated C# (experimental) | **yes if a name used to get a trailing underscore**: see [C# names](#csharp-names) |

## Maven parameters

Every parameter of the Maven goals is required, as in Gradle and the command-line tool. The goals no longer default `baseDir` to `.`, `filePattern` to `src/main/resources/*.bpmn`, `outputFolderPath` to `src/main/kotlin` or `src/main/resources/bpmn-json`, `packagePath` to `de.emaarco.generated` or `outputLanguage` to `KOTLIN`. A missing parameter fails the build naming it.

A relative `baseDir` or `outputFolderPath` resolves against the module's directory, as in Gradle, and no longer against the directory Maven is started in. Configurations that prefix both with `${project.basedir}` keep working unchanged.

## Validation

Generation, the validate task and the testing library run one pipeline on one list of built-in rules, `BuiltInRules` in core.

- **Validate task.** `validateBpmnModels`, `validate-bpmn` and the command `validate` leave out processes marked `isExecutable="false"`, as the API generation does, and fail when two files would be generated under one name. A model the validate task accepts now generates.
- **Testing library.** Mandatory rules can no longer be disabled, and they run when `withRules(...)` leaves them out. `BpmnRules.all()` includes `engine-mismatch` (`BpmnRules.ENGINE_MISMATCH`). With `failOnWarning()`, rules across models run when the models have warnings only.
- **`BpmnValidationService`.** `validate(models, engine)` returns a `ValidationResult` instead of throwing; `collectSingleModelViolations`, `collectCrossModelViolations` and `validateAndNormalize` are gone.

## Rejected models

Every error the user has to fix in the BPMN files is a `RejectedModelException` from core's `domain` package: `BpmnReadException` (a file that is not readable BPMN), `BpmnValidationException` and `ProcessApiNamingException`. `ProcessApiNamingException` no longer extends `IllegalArgumentException`, and a file that cannot be read is no longer a plain `IllegalStateException`. The Maven goals report them as a build failure, the web app with status 400, and every entry point names the file with its path and extension.

## C# names {#csharp-names}

C# no longer renames a name that clashes with a member it declares itself, as no other language does ([ADR 006](/contributing/adr/006-generated-api-shape)). Where 6.x appended `_`, generation now fails and names what to rename:

- an element whose type would be named like another element, as for `task` and `taskNode`,
- a variable named `all`, `inputs`, `outputs`, `processVariables` or `nodeVariables`,
- a call-activity mapping into `inputMappings` or `outputMappings`,
- a shared definition named like its class, such as a message `Messages`.
